# pm - features

What pm can do now. `CHANGELOG.md` says what changed and when; this file says what exists.
Entry format and upkeep: `.claude/skills/features-update/SKILL.md`, completeness pass: `.claude/skills/features-audit/SKILL.md`.
Generated from pm.db: do not edit by hand. Change an entry with `pmctl feature set "<Area>" "<Name>" --text-file -`.

Summary: 174 features in 15 areas.

Guarantees that hold on every page (stated once, not repeated per feature): every change is a POST with CSRF, Origin check, a logged-in session, a tier check and an audit line (the request is refused if the audit line cannot be written); pane text is ANSI-stripped and masked before display and is never logged, indexed or sent to ntfy (the read-only terminal stream is the one unmasked exception); no browser alert/confirm/prompt popups (in-page dialogs only); tmux, git, docker and virsh are called with argv lists, fixed binaries and timeouts, no shell.

## Background

- **Auto-exit sweeper** — Exits idle resumable Claude agents past the timeout (default 24 h, interval 5 min) in tmux sessions matching the `autoexit_sessions` allow-list (default all sessions; `pm*` and pm's own are never touched, independent of `unprotected_sessions`) and closes their window only if nothing else runs there. Changed: 2026-10-13. Code: `src/pm/agents/autoexit.py`, `src/pm/tmux/ctl.py` (`autoexit_settings`), `src/pm/core/config.py` (`autoexit_sessions`).
- **Poll loop and state tracker** — Detects agents in tmux panes every 2 s and publishes state changes. Code: `src/pm/notify/events.py`, `src/pm/infra/snapshot.py`.
- **Chat feed and deliverer** — One background task ingests transcripts into chat items only for agents with an open chat page (or a message in flight), about every second while running and every 5 s idle, links new prompts to outbox messages and publishes `chat_items` events; a second task delivers outbox messages when the agent is idle and publishes `chat_outbox` events. Since: 2026-10-12. Code: `src/pm/agents/chatfeed.py`, `src/pm/agents/deliver.py`, `src/pm/web/app.py`.
- **Event-loop watchdog** — Logs the stack when the loop stalls (2 s) and exits for a systemd restart after 30 s. Code: `src/pm/notify/watchdog.py`.
- **Reload-need check** — On the pm project, tells whether the service needs a restart or only a browser refresh. Code: `src/pm/notify/reloadneed.py`, `src/pm/web/routes/reloadneed.py`, `static/js/pmreload.js`.
- **pm.db daily backup** — Once a day (first run ~60 s after start, then checked every 6 h) pm copies its database `pm.db` (chat items, agent records, and the issue tracker: issues, TODO tasks, CHANGELOG and FEATURES entries) with SQLite's online backup to `<state_dir>/backups/pm-YYYY-MM-DD.db` (folder 0700, file 0600, written to a temp file then renamed) and keeps the newest `db_backup_keep` copies (default 14; 0 turns it off). Errors are logged by type only and never stop pm. `pmctl backup [--force]` makes one now. Where: automatic; `pmctl backup`. Since: 2026-10-13. Code: `src/pm/core/db.py` (`backup`, `start_backup`), `src/pm/core/config.py` (`db_backup_keep`), `src/pm/web/app.py`, `src/pm/projects/tracker/cli_cmds.py` (`do_backup`).

## Tools

- **Agent work claims (`pmctl claim`)** — Agents announce what they are about to change and see who else works on the same files: `pmctl claim add "title" [--path GLOB ...] [--issue N] [--branch B] [--worktree DIR] [--pane %ID]` records an active claim `c<N>` (branch, work tree and pane default to the cwd's branch and work tree and `$TMUX_PANE`; no `--path` = the whole repo; globs where `*` also crosses `/` and a plain path covers everything below it) and prints the other agents' active claims that overlap; `claim list [--all] [--mine]`, `claim show N`, `claim update N [--path ...] [--title]`, `claim done N [--commit sha] [--note]` (prints the overlapping claims to tell), `claim drop N [--note]`, `claim gc`. With `--issue N` the issue gets a note when the claim is added ("claimed by …") and when it is done ("done by … in <sha>"). A claim whose tmux pane is gone is shown as stale, never counts as an overlap, and `gc` drops it (nothing turns stale while tmux cannot be asked). Works in any pm project, tracker files imported or not (only `--issue` needs the tracker); writes pm.db directly like the rest of `pmctl` (works while pm is down, audited, `--json` on every command). Where: `pmctl claim ...`, wrapped by `tmux-agents claim|done|board` (see tmux-agents script). Code: `src/pm/projects/tracker/claims.py`, `src/pm/projects/tracker/cli_claims.py`, `src/pm/projects/tracker/cli.py` (`_claim_parser`), `src/pm/projects/tracker/schema.py` (table `tk_claim`). Since: 2026-10-16.
- **Merge check (`pmctl merge-check`)** — Run in a branch's work tree before merging it: lists the files the branch changes (`BASE...HEAD` plus uncommitted changes), the other agents' active, non-stale claims that cover any of them (own claims, same agent or same work tree, left out) and the repo's other git work trees whose uncommitted changes or commits not in BASE touch them, and warns when BASE has commits the branch lacks (rebase or merge it first; a warning, not an overlap). Exit 0 = clear, 1 = overlap, 2 = error. BASE defaults to the project's main branch. Where: `pmctl merge-check [--base B] [--json]`, `tmux-agents merge-check`. Code: `src/pm/projects/tracker/mergecheck.py`, `src/pm/projects/tracker/cli_claims.py` (`merge_check`), `src/pm/git/ops.py` (`files_since`, `check_base`), `src/pm/git/ctl.py` (`branch_name_ok`). Since: 2026-10-16.
- **tmux-agents script** — Optional single-file Python script (stdlib only, tmux 3.x) for agents working together in tmux: `spawn NAME --agent claude|codex|devin|shell` always opens its own tmux window (detached unless `--focus`, `remain-on-exit` on: the window stays when the agent quits, a dead NAME is respawned in place, only `kill` closes it); address an agent by name, pane id (`%12`) or pm agent id (`claude-7cd08a`, resolved from tmux pane tags, pm.db read-only or the running Claude process, so it works while pm is down); `send` pastes a prompt once the target's screen settles, but holds it in the target's `inbox` while an interactive prompt (permission dialog, y/n, menu) shows and delivers it when that is gone (`--now` skips the checks); the receiver answers with `reply ID [--status done|failed|blocked]`, pasted back into the pane that asked; `broadcast --project NAME` (or `--cwd-under DIR`, `--kind K`) messages every live agent there; `claim`, `done`, `merge-check` and `board` wrap `pmctl claim` / `pmctl merge-check` (see Agent work claims, Merge check) and message the agents whose claims overlap; also `wait`, `result`, `read`, `idle`, `run`, `log`, `ls`, `whoami`. pm itself uses only `tmux-agents id` (the pm agent id of the current pane, for `actor_cmd`). Where: install `deploy/tmux-agents/tmux-agents` to `~/.local/bin`, `tmux-agents help`; guide `deploy/tmux-agents/README.md`, `docs/INSTALL.md` section 10. Code: `deploy/tmux-agents/tmux-agents`. Changed: 2026-10-16.
- **Agent memory (`pmctl memory`)** — Every agent kind (Claude, Codex, Devin, Cursor, ...) keeps and reads the same per-project notes from the shell: `pmctl memory add NAME --type user|feedback|project|reference --description "one line" [--text BODY | --body-file -] [--title T] [--global]` (name: lower-case slug, at most 64 chars), `memory set NAME [--type] [--description] [--text|--body-file] [--title]` (replaces the given fields; adds the memory when missing, then `--type` and `--description` are needed), `memory show NAME` (body, who and when; falls back to the global memory of that name), `memory list [--type T] [--all]` (`--all` adds the global ones), `memory search QUERY [--limit N]` (name, title, description and body, at most 50 hits), `memory rm NAME`, `memory context` (the short index of the project's and the global memories, one line each, for a session start) and `memory sync [--all]`. One memory set per project, shared by all its git work trees; `--global` memories (type `user` only) show with every project. Sync is two-way with Claude Code's own memory dirs (`<claude_dir>/projects/<encoded cwd>/memory`, pm.toml `claude_dir`, default `~/.claude`) of the main work tree and every linked work tree: files Claude wrote or edited since the last sync are imported by hash, a memory changed both in pm.db and on disk keeps pm.db's version and saves the file as `<name>-conflict-<time>.md`, then every project memory is written back with its `MEMORY.md` index (global memories are not written into Claude's dirs), and a memory removed with `rm` loses its file only when nobody edited it since. `add`, `set` and `rm` sync the project right away (a failed sync is a warning; the change is kept); `sync --all` covers every project with memories or a Claude memory dir. A plain summary with the project's and the global memories in full goes to `<state_dir>/memory/<project>.md` for agents without a memory dir of their own. Symlinked dirs or files are refused, nothing is written inside a work tree, files are 0600 and dirs 0700. Like the rest of `pmctl` it writes pm.db directly (works while pm is down, audited before the change with only lengths and hashes of the texts, `--json` on every command). Where: `pmctl memory ...`. Code: `src/pm/projects/tracker/memory.py`, `src/pm/projects/tracker/memfile.py`, `src/pm/projects/tracker/memsync.py`, `src/pm/projects/tracker/cli_memory.py`, `src/pm/projects/tracker/cli.py` (`_memory_parser`), `src/pm/projects/tracker/schema.py` (tables `tk_memory`, `tk_memory_sync`), `src/pm/projects/tracker/gitglue.py` (`worktree_paths`). Since: 2026-10-17.
